# Supraj.dev Visual Language

## Intent

Supraj.dev artwork should feel like a premium technical publication: clear enough to teach, polished enough to feature, and distinctive enough to recognize without relying on a logo.

## Core characteristics

- strong focal point
- clear visual hierarchy
- meaningful technical symbolism
- restrained depth and lighting
- generous negative space
- editorial polish
- modern but not trend-chasing
- technically credible

## Preferred visual building blocks

Use real engineering concepts whenever possible:

- nodes and service boundaries
- request/response or data flows
- clusters, pods, services, ingress
- GPU, memory and inference paths
- agent/tool/memory relationships
- pipelines and deployment stages
- certificates and trust chains
- APIs, queues and databases
- observability traces and signals
- identity and policy boundaries

## Color direction

Supraj.dev's publication UI is light-first with near-black text and a restrained cobalt/indigo accent. Artwork does not need to use the exact same background every time, but it should harmonize with that system.

Good default direction:

- neutral, warm-light or deep-neutral base
- cobalt / indigo as a recurring accent
- cyan only as support, not as a mandatory glow
- strong contrast
- limited palette per artwork

Avoid rainbow gradients and neon overload.

## Typography inside artwork

The webpage already carries the article title. Treat artwork text as a visual label, not as content.

- 1–5 words maximum by default
- large enough to remain legible at card size
- no paragraph text
- no code snippets as decoration
- no duplicated article title unless the asset specifically needs it, such as some OG cards

Examples:

- CUDA
- TRUST CHAIN
- AGENT RUNTIME
- CACHE HIT
- RETRIEVE → GENERATE

## Composition

A useful default structure is:

1. one dominant focal object or relationship
2. one secondary context layer
3. subtle supporting depth/background

Do not fill every empty area. Negative space is part of the design.

## Thumbnail test

At a glance, the viewer should be able to answer at least one of these:

- What technology is this about?
- What system relationship is being explained?
- What engineering problem is involved?

If the artwork only communicates "technology" or "AI", it is too generic.

## Hero test

The hero should deepen the thumbnail idea. It should not simply be a stretched crop. It may reveal more of the system, flow, environment, or failure/trust boundary while remaining visually related.

## What to avoid

Do not default to:

- humanoid robots
- glowing brains
- generic clouds
- hacker hoodies
- giant vendor logos
- floating random code
- fake terminal text
- meaningless holograms
- cluttered pseudo-diagrams
- stock-photo compositions
- repeated blue-purple gradient cards
- identical layout across every article

## Quality bar

A good Supraj.dev visual should be useful even without the title. It should look like an editorial explanation of an engineering idea, not decorative filler.
